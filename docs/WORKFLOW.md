# 評議流程

| 階段 | 輸入與輸出 | 屏障與可見性 |
|---|---|---|
| 0 收件 | 標題、說明、背景、目標、限制、選填證據；配置唯一 ID | 不補造背景；先驗證輸入與封存設定 |
| 1 獨立初評 | 十二份初評、三個疑慮、假設、缺口、信心與四維評分 | 每人只看原提案與自己的角色，全部保存後才進辯論 |
| 2 對抗辯論 | 正反開場各一次、正反反駁各一次 | 開場彼此不可見；反駁只看兩份開場，不延伸第二輪 |
| 3 最終評估 | 每人自己的初評、相同辯論包；終票、理由、變動、風險、實驗與推翻條件 | 優先續接；否則全新上下文，不提供其他陪審輸出 |
| 4 彙整 | 初終票數、缺件、重試、立場變化與假設 | 驗證 ID 唯一、票種、完整性；失敗不算棄權 |
| 5 少數檢視 | 異議、尾端風險、共同假設、相關偏誤 | 無嚴格多數時保留全部分歧，不稱為多數共識 |
| 6 報告 | 十四節繁體中文 Markdown 與 JSON | 逐條標註個別來源；不新增未在輸出出現的論據 |

每次完整評估需 28 次成功任務輸出：12 初評 + 2 開場 + 2 反駁 + 12 終評。若續接可用，終評仍是一次真實新推論，不能直接複製初評。模型上下文可以保留，也可依規則重新建立。重試不計入這 28 次成功輸出的基數。

## 投票與評分

- `SUPPORT`：支持；`OPPOSE`：反對；`CONDITIONAL`：需滿足明列條件；`ABSTAIN`：證據不足而棄權。
- 初評與終評各自計數。失敗與缺件單獨列出，不填假票、不改成棄權。
- 嚴格多數須超過該階段有效輸出的一半；棄權是有效輸出，但不會形成支持建議。
- 平手或僅有相對多數時不宣稱嚴格多數。缺少任一初評、終評或辯論時，整體建議暫緩。
- `changed` 必須等於初終票種不同；初評失敗時必須為 `null`。程式不替代理改寫該欄位。
- 四維評分與信心皆為 1–5 序位，見 [共用量表](../src/agent_council/data/rubric.md)。風險越高越不利，不加總或推算普遍成功機率。

## 證據與異議

`user_provided` 只代表提案提供，並非查證。`assumption`、`speculation` 與 `unverified` 分別表示假設、推測與未查證主張。本版代理無工具，因此拒收 `verified` 外部主張；未來研究後端可另行設計可稽核的查證機制。

報告列出每位終評的假設、風險、未解問題與可推翻條件，讓多數未採納的異議仍然可見。字面相同、超過六位共享的假設會另外列出；有不同票種時列出各自的假設供比較。終評另以 `disputed_assumptions` 與 `contradictions` 指出明確質疑及兩個矛盾來源；程式拒絕引用該角色不可見或缺失的材料。這些判斷保留陪審來源，並非額外獨立查證或自然語言矛盾的自動證明。

## 失敗處理

`max_retries` 是初次嘗試之外的重試次數，預設一。無效輸出保存原文後依預算重試，不進計票。原生執行還沒收到回覆時，狀態保持 `awaiting_native`；不以等待時間推斷失敗。

代理工具報錯時，主代理執行 `native fail` 並附原因，再 `native advance`；仍有預算則發布同任務下一次嘗試，否則標記 `failed`。後續階段明確收到 `null` 缺件，不會收到由協調器補寫的觀點。所有階段結束後仍會產生標明「不完整」的報告。

# 第二輪：條件式驗證

只在第一輪全部處理並鎖定後決定是否啟動。父代理建立具體待驗證主張與 Claim ID，
附支持／反對的來源片段、未知資訊及「會如何改變決策」，不預設要證實哪一方。

## 觸發矩陣

| 條件 | 行動 |
| --- | --- |
| 重要事實互相矛盾 | V01 查來源、適用範圍、版本與日期 |
| 任一角色提出有根據 HIGH / CRITICAL 風險 | V02 查失敗模式、後果與緩解 |
| 至少三位 core_evidence_insufficient=true | V01 查核心證據缺口 |
| 涉及安全、法律、重大財損或高度不可逆後果 | V02；需要具體事實查核時再加 V01 |
| 可能直接推翻最終建議的爭議 | 依主張性質選 V01 或 V02，必要時兩者 |

有根據重大風險可由 packet 已知事實、來源、或明確說明的因果失敗鏈支撐。
父代理必須人工語意檢查主張的重要性、grounding 是否可信、是否事實衝突；
不能只靠 severity 字串。維護工具提供保守的候選觸發，不代替判讀。
偏好或價值權重不同不是事實矛盾；若沒有任何觸發，記錄原因並跳過第二輪。
HIGH-STAKES 即使全票支持也必須驗證，不受多数票否決。

## 派發與限制

- 最多兩個驗證角色：V01 Fact Verifier、V02 Risk Auditor，各一個獨立 context。
- 每個角色最多一次恢復重試；重試不增加驗證角色種類或投票數。
- 只傳中立 packet、指派主張、必要的證據摘錄及
  `schemas/verification_result.schema.json`，不需傳所有第一輪推理或票數。
- 可看待驗證的主張與證據，但仍不得讀取 peer 檔案或互傳訊息，不可再委派。
- 每個主張只能是 CONFIRMED、REFUTED、PARTIALLY_SUPPORTED 或 UNRESOLVED。
  引用實際查閱來源，分清事實與推論，說明限制、反證及對決策影響。
- 若沒有工具、無法存取來源或證據仍不足，保留 UNRESOLVED，不偽造來源。
  驗證角色完全失敗時，由主代理記錄「未完成，主張仍 UNRESOLVED」，不得
  冒寫該角色 JSON。首輪有效結果保留不動。
- 查證不是新增投票，不得重投、修正第一輪票或改變其分母。

## 綜合決策

可信且未緩解的致命缺陷可導向 NOT_RECOMMEND；主要事實待解可導向
INSUFFICIENT_EVIDENCE；可驗證條件與可逆試驗可導向 CONDITIONALLY_RECOMMEND。
沒有重大風險不自動等於 RECOMMEND，仍需目標、價值與可行性證據。
少數意見如被 REFUTED 也保留其原票，並說明新證據如何影響最終判斷。
